# 情报推送对接说明（给外部搜索 Agent 用）

> 角色分工：**你（外部 Agent）负责搜索和搬运，本系统负责入库、校验、去重、交叉核实、归档。**
> 本系统不配置任何搜索 Key。归档内容**永不自动发布**，仅作明哥的谈资素材（需求 §7）。

你的职责只有三件事，越简单越好：

1. 按本文件的「搜索指导」检索
2. **不要生成任何文案、不要改写标题** —— 只搬运「标题 / 链接 / 一句话摘要」
3. POST 过来

---

## 一、搜索指导（搜什么、怎么挑、什么不推）

### 检索主题

| 主题 | 参考关键词 | 说明 |
|---|---|---|
| 口岸动态 | 深圳灣口岸 / 蓮塘口岸 / 港珠澳大橋口岸 / 沙頭角口岸 / 口岸通關安排 | 开放时间调整、维修、节日安排、客流措施等官方动态 |
| 两地牌政策 | 粵Z 兩地牌 / 港車北上 / 粵車南下 / 兩地牌 新政 / 兩地牌 配額 | 申请条件、配额、流程、验车要求的变化；**港车北上政策调整重点关注** |
| 香港车市 | 香港 新車 / 香港 車市 行情 / 香港 電動車 / 埃爾法 香港 / Alphard 香港 | 香港进口车行情、热门车型动态 |
| 税务与合规 | 香港 首次登記稅 / 跨境車輛 保險 / 兩地牌 稅務 | 与两地车辆相关的税务、保险、合规资讯；政策解读类优先 |
| 跨境交通基建 | 港深西部鐵路 / 北部都會區 交通 / 新口岸 規劃 | 影响跨境出行的大基建动态，属长期谈资 |

> 以上主题也可通过 `GET {HOST}/api/intel/topics` 动态获取（公开接口，无需鉴权），以系统内最新口径为准。

### 挑选标准

- 只推**白名单域名**内的官方公告、政策原文或主流媒体报道（白名单见下）
- 优先推**近 7 天内**的资讯；发布超过 3 个月的旧闻不要推
- 标题保留原文，不要改写或渲染

### 时效性（重点，曾出过实际事故）

> 2026-10 实际推送中混入了《電動車龍頭品牌將易主？比亞迪 2025 年度銷量有望超越 Tesla》——2026 年 10 月还在把 2025 年当展望讨论，这是典型的**旧闻翻炒**：搜索引擎不加时间过滤时，「香港 電動車」这类词返回的常是历史热门旧文。

请遵守：

1. **搜索时务必用引擎的时间过滤**（近一周 / 近一月），不要用「不限时间」的默认结果
2. **推送前检查标题的年份口径**：已经过去的年份，不得再以展望/推测语气出现（「有望」「預計」「將會」「劍指」等 + 已过年份 = 旧闻，不推）。例：2026 年见到《2025 年度銷量有望超越 Tesla》→ 不推
3. **尽量带 `publishedAt` 字段**：系统会拒绝发布超过 3 个月的条目；不带也能推，但系统会对标题做上述年份口径检查，命中会被拒并给出原因
4. 历史盘点/回顾类（**非展望语气**，如《回顧 2025 年度車市十大事件》）可以推，但须确认仍有谈资价值
5. 可调 `GET {HOST}/api/intel/topics` 获取 `now`（系统当前日期）与 `recency` 参数，以系统口径为准，不要依赖你自己的时钟

### 不要推

- **涉政内容、政治人物相关一律不搜不推**（系统会拦截，浪费你的额度）
- 中介广告、软文、营销号内容（白名单过滤会拒绝）
- **过期展望类旧闻**（见上方时效规则，系统会拒绝并返回原因）
- 与口岸 / 两地牌 / 车市 / 跨境交通无关的内容

### 频率

- **每天 1 次为宜**；最低每周 1 次（建议周一 08:00 前后，与系统默认节奏对齐）
- 重大新政可即时追加推送，不必等下一次排程
- 不用担心重复：同一 URL 或标题重复推送会被自动跳过，不算错误

## 二、快速自检（对接前先跑这两步）

```bash
# 1. 确认推送通道已启用（未配置 token 会返回 503）
curl -s -X POST {HOST}/api/intel/push \
  -H "Content-Type: application/json" \
  -H "x-push-token: {INTEL_PUSH_TOKEN}" \
  -d '{"source":"对接自检","items":[{"title":"自检测试","url":"https://www.hk01.com/test/1","snippet":"x"}]}'
# 期望：{"ok":true,"accepted":true,...}

# 2. 请管理员在网页「INTEL · 情报线」区块确认已出现该条目与推送时间
```

## 三、接口

```
POST {HOST}/api/intel/push
Content-Type: application/json
X-Push-Token: {INTEL_PUSH_TOKEN}
```

`{HOST}` 与 `{INTEL_PUSH_TOKEN}` 由本系统管理员提供。token 也可放请求体：`{"token": "...", "items": [...]}`。

### 请求体

```json
{
  "source": "你的Agent标识",
  "items": [
    {
      "title": "标题（必填，≤200字）",
      "url": "https://完整链接（必填，必须 http/https）",
      "snippet": "一句话摘要（选填，≤800字）",
      "publishedAt": "2026-10-03T08:00:00Z"
    }
  ]
}
```

| 字段 | 必填 | 约束 | 说明 |
|---|---|---|---|
| `source` | 否 | ≤50 字 | 标记数据来源，会记入归档与「最近推送」展示 |
| `items[].title` | **是** | ≤200 字 | 超过自动截断 |
| `items[].url` | **是** | 必须 `http://` 或 `https://` | 非白名单域名会被拒 |
| `items[].snippet` | 否 | ≤800 字 | 超过自动截断 |
| `items[].publishedAt` | 否 | ISO 8601 | **参与时效校验**：超过 3 个月的旧闻会被拒；强烈建议尽量带上 |

`items` 单次最多处理 **200 条**。

## 四、响应与错误对照

| 状态 | 含义 | 你该做什么 |
|---|---|---|
| `200 {"accepted":true,"added":N,...}` | 成功入库 N 条 | 无 |
| `200 {"accepted":true,"added":0}` | 全部与已归档重复 | 正常，无需处理 |
| `400 {"accepted":false,"reasons":[...]}` | 条目被拒（缺字段 / url 非法 / **非白名单来源** / **发布时间过旧（超过 3 个月）** / **标题时效性存疑（旧闻翻炒）**） | 检查 reasons 数组：来源问题换白名单内的源；时效问题换新资讯 |
| `401 {"error":"推送 token 无效"}` | token 错 | 找管理员核对 `INTEL_PUSH_TOKEN` |
| `429`（含 Retry-After） | 失败尝试过多被限流 | 停止重试，等窗口（10 分钟）过后再试 |
| `503 {"error":"未配置 INTEL_PUSH_TOKEN..."}` | 系统侧未启用推送 | 找管理员在 .env 配置 |

成功响应示例：

```json
{"ok":true,"accepted":true,"received":5,"added":3,"rejected":2,"verified":1,
 "reasons":["非白名单来源: https://www.hzmauto.hk/cbp-invest", "..."]}
```

`verified: N` 表示有 N 条被 ≥2 个独立白名单域名交叉印证（多源核实）——这只是标记，不影响入库。

## 六、本系统收到后自动做的事（你不用管）

1. **白名单域名过滤**：非白名单来源直接拒绝
2. **去重**：URL 或标题重复则跳过
3. **多源交叉核实**：同一主题（标题前 6 字归一）出现 ≥2 个独立白名单域名 → 标记 `verified: true`
4. **归档**到 `data/intel.json`，标注来源与核实状态；网页「INTEL · 情报线」区块可浏览（含推送通道状态与最近推送时间）

归档内容**永不自动发布**（需求 §7 硬约束）。
